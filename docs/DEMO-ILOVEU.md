## 1. 已经定下来的事

| 事项 | 结论 |
|---|---|
| 卡片结构 | 一首歌一张卡，**左右滑动翻页**；页码圆点表示当前在第几页 |
| 切歌 | 用控制栏按钮，不用滑动 |
| 控制栏 | 固定在卡片下方，不跟着翻页：`⏮ 上一首` `✕ 不喜欢` `▶ 去听` `♥ 喜欢` `⏭ 下一首`，下面一行写"第 n 首，共 6 首" |
| 不喜欢 | 记反馈，并**自动切到下一首** |
| 第 1 页 | 封面（有用户照片时，点击翻到照片）、歌名、歌手、**为什么现在推荐它** |
| 第 2 页 | 歌词全文，静态显示（应用拿不到播放进度，做不了滚动同步） |
| 第 3 页 | 歌曲故事（**事实和解读分开**，事实逐条标出处）+ 歌曲档案 |
| 第 4 页 | 你和这首歌：初见、第一次去听、心动三个时刻，加统计（界面原叫"初听"，G12 改名；数据字段仍是 `heard`） |
| 封面背面 | 只放用户自己的照片。没有照片时封面不能翻。**AI 另类封面已砍掉（Fano 10-05）** |
| 歌手字段 | 写**洛天依**（演唱，G6 核实）；作词苍十三、作曲 / 编曲 / 调教 / PV 阿良良木健、曲绘历历路路写在档案里。**Fano 10-05 确认** |
| 能量、情绪标签 | **保留，但界面上不显示原始数字**（Fano 10-05：不要让用户看到意义不明的东西）。能量和情绪是推荐算法的内部字段，界面上一律改用文字描述，见 §3.6 |
| 歌词页 | 保留。应用改为自用，不上架 App Hub |
| 配色 | **A 夜空**，整个应用统一（Fano 10-06） |
| 歌曲卡入口 | 歌单和曲库都能进；卡片左上角「‹」返回原列表（§3.7） |
| 歌单行按钮 | **只留"去听"**，喜欢 / 不喜欢在卡片里点（Fano 10-06） |
| 主界面 | **三步卡片**：① 你在做什么 → ② 有什么要求 → ③ 歌单，点选后自动进入下一张（Fano 10-06，§3.7） |
| 演示设备 | 用桌面版。手机端 OctoSense 不支持侧载脚本应用（平台文档原话："An arbitrary bundle cannot be side-loaded onto a stock OctoSense phone"），10-06 放弃 Android 演示 |

## 2. 平台约束（只列和 Demo 有关的）

出处：OctoScript-App-Design-Flow `docs/SCRIPT-API.md`、`docs/CAPABILITIES.md`。

| 约束 | 影响 | 对策 |
|---|---|---|
| `model.complete` 只返回文字，不能出图 | 应用内无法让 AI 画封面 | Demo 用预制图片；之后改为"AI 给参数，应用用色块画"（见 §9） |
| **没有文件选择器**，不能读相册 | 用户不能从相册选照片上传 | 手机上用 `CameraPreview` 拍照存进应用存储；Demo 阶段由 GPT 手动放文件；同时向平台提 issue，申请只读的单张图片选择器（G11） |
| 应用不播放音频 | 没有进度条，歌词不能跟唱滚动 | 去掉进度条；歌词静态显示 |
| 文档里没有旋转和动画接口 | 封面"一直转"不一定做得到 | G7 限时调研；做不到就用静态唱片造型 |
| `GestureView` 的滑动和 `ScrollYView` 的滚动能否嵌套，文档没写 | 歌词页、故事页文字长，需要上下滚 | G8 实测；冲突的话改成"摘要 + 点开全文" |
| 存储：单个文件 ≤ 1 MiB，整个应用 ≤ 16 MiB，≤ 256 个文件 | 图片要压缩 | 每张图压到 300 KB 以内；`manifest.json` 声明 `storage.max_bytes` |
| `Image` 读本地图片要用 `load_image_from_data_async(fs.read_bytes(path))` | 图片必须先在应用存储里 | 所有图片放应用存储的 `covers/` |
| `ButtonFlat` 里不能放子组件 | 封面、整行可点区域 | 用 `GestureView{on_tap: ...}` 包住 |
| `View` 的背景色在 card-host 里不显示 | 卡片底色 | 一律用 `SolidView` / `RoundedView` |

## 3. 设计规格（Claude 负责，GPT 照此实现）

### 3.1 颜色

| 名称 | 色值 | 用途 |
|---|---|---|
| 深海底 | `#x0B1526` | 页面背景 |
| 夜蓝卡 | `#x14223A` | 卡片、面板 |
| 抬升蓝 | `#x1C2E4D` | 次按钮、未选中标签、推荐理由底 |
| 描边蓝 | `#x2A4366` | 未选中圆点、分隔线 |
| 天依蓝 | `#x66CCFF` | 当前页圆点、喜欢、主按钮、强调文字 |
| 霜白 | `#xE6F1FA` | 正文、歌名 |
| 雾蓝灰 | `#x8FA3BC` | 次要文字、来源标注 |
| 提示橙（10-06 新增） | `#xE8B04B` | **只用于提示**：模拟定位、测试数据、演示数据 |

规则：天依蓝上的文字一律用深海底色（`#x0B1526`），不用白字。

### 3.2 尺寸

- 卡片圆角 24，内部小块圆角 16，标签圆角 16，按钮圆角为高度的一半
- 可点区域至少 44 × 44
- 字号：歌名 28 粗体；页标题 22；正文 14；次要文字 12–13

### 3.3 各页布局

画布「情境 DJ · 天依蓝配色」里已画好：配色表、第 1–4 页、封面背面、空状态，以及第 6 行「主界面 · 天依蓝（统一后）」的主界面和曲库。GPT 实现时以画布为准，有冲突以本节文字为准。

### 3.4 状态（每页都要有）

| 页 | 有数据 | 没有数据 |
|---|---|---|
| ① 封面 | 显示封面图 | 显示静态唱片造型 + 歌名首字 |
| ① 背面 | 用户照片 | 没有照片时，点击封面无反应，也不显示"轻点翻面" |
| ② 歌词 | 全文 | "还没有歌词" + 说明怎么添加 |
| ③ 故事 | 事实 + 解读 + 档案 | "还没有这首歌的故事"；档案只显示已有字段，缺的字段不显示 |
| ④ 相遇 | 时间线 + 统计 | "你们还没有正式见过面"。**模拟定位产生的记录标"测试数据"** |

### 3.5 标注规则（如实标注，不能省）

- 封面背面：右下角小字「你的照片」
- 故事页：每条事实后标出处（如「B 站投稿简介」）；解读部分标题写「解读（AI 整理，可能不准）」
- 演示数据：页面顶部一条「演示数据」提示

### 3.6 能量和情绪：保留，但不显示数字（Fano 10-05）

- **它们是干什么的**：每个活动有一个目标能量（学习 1.5、睡前 1.0、通勤 3.4、运动 4.7……），本地规则按"歌的能量离目标有多远"打分，所以学习时推安静的歌、运动时推带劲的歌。情绪用来配合天气和你说的话（比如"下雨天有点丧"）。AI 选歌时也会看这两个字段。**删掉能量，这首歌在本地规则下几乎不会被推荐出来。**
- **界面上不显示原始数字**。现在有两处显示了数字：推荐理由里的"能量4/5 合「散步」"（`main.splash` 约 1040 行）和曲库列表的"能量4 · …"（约 1408 行）。改成文字：1 安静、2 舒缓、3 适中、4 轻快、5 激烈，例如"节奏轻快，合「散步」"。这一处改动由 Claude 在 `main` 上做，GPT-A 的歌曲卡只用文字描述，不显示数字。
- **《I LOVE U》的标签（Claude 建议，Fano 可改）**：`en: 4`（轻快的电子流行）、`vo: true`（女声）、`md: "欢快"`、`lg: "zh"`。SEED 条目：`{t: "I LOVE U" a: "洛天依" en: 4 vo: true md: "欢快" lg: "zh"}`。

### 3.7 整个应用统一配色和跳转（Fano 10-06 确认）

**已定**：配色正式定为 **A 夜空**；主界面、曲库、感知页全部改用天依蓝，和歌曲卡一致。画布第 6 行「主界面 · 三步卡片（统一后）」是示意，可以点 Play 试跳转（① 点「放松」→ ② 点「甜一点」→ ③ 点第 2 首 → 封面页 → 左上角返回）。

**颜色对应**（主界面现在 → 换成 §3.1 的哪个常量）

| 主界面现在 | 换成 | 用在哪 |
|---|---|---|
| 近黑背景 | 深海底 | 页面背景 |
| 灰色卡片 | 夜蓝卡 | 情境区、歌单行 |
| 橙黄（选中的标签、"下一步"） | 天依蓝，上面的字用深海底色 | 主按钮、选中状态（用定位 / 用时段 / 用天气、选中的城市） |
| 未选中的标签 | 抬升蓝 | 候选活动、未选中的城市、歌单行的"去听" |
| 灰白文字 | 霜白 / 雾蓝灰 | 正文 / 次要文字 |
| "模拟定位中"等提示 | **提示橙**，底色用同色 14% 透明 | 只用于提示：模拟定位、测试数据、演示数据 |

- 天依蓝只给**可点的和选中的**；提示橙只给**提示**，不做按钮。第 4 页的"测试数据"标签也改用提示橙。
- 所有颜色引用文件顶部同一组常量，不在别处写色值。
- 圆角、字号、可点区域按 §3.2。

**主界面改成三步卡片（Fano 10-06）**：原来的长页面（情境、候选、补充要求、歌单从上到下排）拆成三张卡片，一次只显示一张，点选后自动进入下一张。画布第 6 行 ①②③。

| 步骤 | 内容 | 怎么进入下一步 |
|---|---|---|
| ① 你在做什么 | 情境摘要（时段、天气、移动、地点，右上角「改情境 ›」展开原来的 用定位 / 用时段 / 用天气 / 城市）；问题"你现在在做什么？"；候选活动做成大块按钮，最可能的那个用天依蓝描边；下方写依据 | **点一个活动**：记下确认（写 `labels.json`），自动进 ②。底部「不确定，先按推断继续 →」也能进 ②，但**不记确认** |
| ② 有什么要求 | 顶部小标签显示上一步的结果（如"放松 · 在家 · 小雨 18°C"），点它回 ①；问题"还有什么要求吗？"；常用要求做成标签；下面是输入框 | **点一个常用要求**：直接开始选歌，进 ③。或者在输入框写一句再点「选歌」。或者点底部「没有要求，直接选」 |
| ③ 歌单 | 顶部小标签显示 ①② 的选择，点它们回对应的步骤；AI 理解；歌单 | 点一首进入歌曲卡；底部「从头再选一次」回 ① |

- 每一步左上角「‹」回上一步；顶部用圆点表示第几步，样式和歌曲卡的页码圆点一样。
- **选歌期间**：进入 ③ 后立刻显示"AI 正在理解情境并选歌…"，结果出来后替换。这样就不会再出现今天那种"点了没反应"。
- 常用要求先用固定的 6 个：甜一点、安静一点、带劲一点、不要人声、只听中文、来点没听过的。点一个就走，**不支持多选**；要组合就自己写一句。
- **确认可以撤销**：从 ② 回到 ① 换一个活动时，要**替换**刚才那条确认，而不是再加一条。今天实测发现"再点一次取消"只撤掉了界面，`labels.json` 里的记录还在，这里必须一并修好。

**歌曲卡的跳转**

| 动作 | 结果 |
|---|---|
| 点歌单里某一行（歌名、理由区域） | 进入这首歌的歌曲卡，第 1 页 |
| 点曲库里某一首 | 同上。曲库行有卡片内容的显示小标签「有故事」 |
| 卡片里的 ⏮ / ⏭ | 在**进来的那个列表**里切歌；"第 n 首，共 m 首"按这个列表计数 |
| 卡片左上角「‹」 | 回到原列表（能保留滚动位置最好，做不到就回顶部） |
| 在卡片里点 ♥ / ✕ | 回到列表后，那一行状态同步（喜欢的歌名后显示小心形） |
| 卡片左上角「‹」回到歌单 | 回到 ③，不重新选歌 |

**歌单行**：只留"去听"一个按钮，喜欢 / 不喜欢都在卡片里点。整行（除"去听"外）可点，右侧加 › 提示能进入。

**曲库行**：歌名 + "歌手 · 节奏 · 人声 · 语种"，节奏用 §3.6 的文字，不显示数字。

## 4. 数据（都在应用存储里，**不进 git**）

### 4.1 歌曲卡内容 `accounts/device/cards.json`

```json
[{
  "k": "I LOVE U|洛天依",
  "story": {
    "facts": [{"text": "……", "src": "出处名称", "url": "https://……"}],
    "reading": "解读正文",
    "by": "preset"
  },
  "archive": {"credits": "作词 / 作曲 / 演唱 ……", "date": "首发日期", "where": "首发平台", "note": "其他"},
  "lyrics": "lyrics/iloveu.txt",
  "covers": {"front": "covers/iloveu-front.jpg", "user": ""}
}]
```

- `story.by`：`preset`（预制）或 `ai`（应用内生成），界面据此标注
- 路径都相对于应用存储根目录；文件不存在时按"没有数据"处理

### 4.2 第一次相遇 `accounts/device/encounters.json`

```json
[{"k": "歌名|歌手",
  "seen":  {"at": 0, "slot": "晚上", "weekend": false, "act": "relax", "place_kind": "home",
            "motion": "still", "weather": "小雨 18°C", "city": "合肥", "intent": "想听甜一点的", "sim": false},
  "heard": null,
  "liked": null}]
```

- `seen`：第一次出现在歌单里；`heard`：第一次点"去听"；`liked`：第一次点"喜欢"
- **每个时刻只记第一次，之后不再覆盖**。例外：已有的是模拟记录（`sim: true`），之后出现真实记录时替换
- 不存坐标，只存地点类型。删除曲库里的歌不删这里的记录
- 天气不可用时 `weather` 为空字符串；城市只在天气按城市查询时记录，按定位查询时为空
- 启动时按 `run_chunks` 分批读取（AGENTS.md 的指令上限规则）

### 4.3 文件放哪

| 内容 | 位置 | 进 git 吗 |
|---|---|---|
| 歌曲卡文案（故事、档案） | 应用存储 `accounts/device/cards.json` | 不进。文案草稿另存 `<本机工作目录>\demo-iloveu\copy\` |
| 歌词 | 应用存储 `lyrics/iloveu.txt` | **绝不** |
| 官方封面、用户照片 | 应用存储 `covers/` | **绝不** |
| 素材原件、调研记录 | `<本机工作目录>\demo-iloveu\` | 不进 |
