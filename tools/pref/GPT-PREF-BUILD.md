## 2. 规格

所有数值行为以 `PREF-REF.py` 为准，本节只说接口和挂点。

### 2.1 常量（放在 `[PREF]` 区顶部）
`PREF_ON = true`、`TOPK = 12`、`PREF_ETA = 0.5`、`PREF_R = 2.0`、`PREF_BETA_MAX = 3.0`、`PREF_P = 1000003`、`PREF_CAP = 600`。
`TOPK = 0` 表示"不截断，全部可选"，只在回归测试副本里用（§3 V7）。

### 2.2 特征与 BPM
- `pref_x(s)` 按参考实现 `features()`，返回 12 维数组。
- BPM 放在单独的常量表 `let SEED_BPM = {...}` 里，以 `key_of(s)` 为键，**不改 SEED 的行**。代码先按空表写；10-11 22:00 后泛舟给出 `bpm.json`，单独提交一次 `data: add BPM`，然后重新生成 `PREF-EXPECTED.json` 并重跑 V3。
- 用户自己添加的歌没有标签，特征除 BPM 外全为 0，这是已知限制。

### 2.3 并列定序哈希
```
key = 种子 + "|" + 歌名 + "|" + 歌手
h = 0
对 key 的每个字符 c：h = (h*31 + 码点(c)) mod 1000003
重复 2 次：h = (h*h + 12345) mod 1000003
```
- 先查运行时有没有现成的哈希函数且 Python 能逐位复现；有就用它，并在 REPORT 写明，同时重新生成期望值。没有就用上面这个。
- **拿不到字符码点就停下报告**，不许自己换算法。
- 所有中间值都 < 10¹²，双精度下精确；实现后必须用 V2 逐个核对。

### 2.4 种子
- 每次推荐用一个种子做并列定序。优先用这次推荐写入日志时的 rec 事件 id；排名时 id 还没分配的话，就预留一个唯一值。
- **不管用哪种，都要把实际用到的种子写进 rec 事件的 `ts` 字段**，O 用它复算。
- 同一次推荐的首轮和重试必须用同一个种子。
- 种子转成字符串时必须与 Python 的 `str(int)` 一致（例如 `"1"`，不能是 `"1.0"`）；V2 会抓这个错。

### 2.5 排名与候选（挂点：`rec_snapshot`、`ask_model`、`local_pick`）
- 新函数 `pref_rank(ctx, it, elig, seed)`：对硬条件允许的歌计算 $b$（调用 `score_song` 前置 `jitter_on = false`，算完恢复）、学习项和 $s$，按 §1 排序，返回带 `rank` 的列表。
- `rec_snapshot`：硬条件得到 `elig` 后，再用 top-K 掩码收窄，作为模型路径的 `elig`。守卫照常用 `snap.elig` 检查，**错误码不新增**。
- `ask_model`：`cands` 按名次顺序构造，每项加 `rank` 字段（从 1 开始）；`task` 末尾加一句："songs 已按本地分从高到低排列（rank 1 最高），没有特别理由时优先靠前的。" schema 不变。
- `local_pick`：改为按 `pref_rank` 的顺序取 6 首，同一歌手最多 2 首，对应参考实现 `local_six()`。不再使用随机抖动。

### 2.6 评价表 `pref_votes.json`（挂点：`feedback()` 末尾，与 `dlog_rate` 并列）
- 每行：`{n, r, k, a, y, L}`。`n` 是持久的递增序号；`r` 是推荐 id；`k` 是歌曲键；`a` 是 `playlist_act`；`y` 为 1 或 0；`L` 是**这张歌单当时的 6 首歌曲键**。
- 只收这些票：`feedback_act != ""`、`sim.kind == "off"`、`e_link(i)` 能定位到推荐、能拿到该推荐的 6 首。其他票只走现有单曲反馈。
- 同一 (r, k) 再次评价时，删掉旧行，追加一行新的（拿新的 n），对应参考实现 `apply_vote()`。界面若有撤销操作，撤销时只删行。
- 写文件：每个处理函数只写一次，`booted` 之前不写，写法与 `save_feedback` 一致。超过 `PREF_CAP` 时删掉 n 最小的行。

### 2.7 重放与在线更新
- 启动时在 labels 之后加一步 `pref`：读 `pref_votes.json`，按 n 升序重放，得到每个活动的 `{v, beta, n}`。单次处理不完时（例如超过 200 票），用 `start_timeout` 分批接续。启动页步骤名显示"偏好"。
- **新增一行**：只对这一票做一步更新，结果与全表重放相同。**改票或撤销**：全表重放。
- 指数函数用运行时自带的；没有 `exp` 就停下报告。
- 参数**不单独存文件**，评价表是唯一事实来源。

### 2.8 偏好说明（本地生成）
- 当前活动的权重里，绝对值最大的一项 ≥ 0.25 时，在歌单说明前面加一句小字："偏好：你在「通勤」时较少选英文歌"。
- 措辞表：

| 特征 | 正号 | 负号 |
|---|---|---|
| 能量 | 较常选节奏强的歌 | 较常选安静的歌 |
| 人声 | 较常选带人声的歌 | 较常选纯音乐 |
| BPM | 较常选快歌 | 较常选慢歌 |
| 某种情绪 | 较常选 X 的歌 | 较少选 X 的歌 |
| 中文、英文 | 较常选中文歌、英文歌 | 较少选中文歌、英文歌 |

- 不加"可能""仅供参考"之类的措辞。不进模型输入。

### 2.9 调试页
新增一组，显示：当前活动的票数、β、绝对值最大的三项权重；本轮前 12 首，每首显示名次、规则分、学习项、学习前名次（同一种子、学习项置 0 时的名次）。
